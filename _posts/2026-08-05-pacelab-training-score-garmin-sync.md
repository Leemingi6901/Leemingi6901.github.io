## 1️⃣ 훈련 점수 — 컨디션(TSB) 빼고 순수 실행력만

처음엔 그날의 컨디션(TSB, 훈련 부하 밸런스)과 페이스 정확도를 섞어서 채점했는데, 생각해보니 이상했습니다. **훈련 외 일상생활이 컨디션에 미치는 영향이 러닝 훈련 자체보다 큰데**, 그날 컨디션이 나빴다고 훈련 점수까지 깎이는 건 "내가 그 강도를 얼마나 잘 실행했는가"라는 질문과는 다른 이야기였거든요. TSB 관련 로직(`LOAD_FIT_BANDS`, `loadFitScore`)을 전부 들어내고, 페이스가 목표 강도 구간 한가운데를 얼마나 정확히 찍었는지 하나로만 채점하도록 바꿨습니다.

```ts
export interface TrainingScore {
  score: number; // 0~100 — 컨디션과 무관하게, 강도를 얼마나 정확히 실행했는지만
  zone: IntensityZone;
  breakdown: string[];
  suggestions: string[];
}
```

## 2️⃣ 강도 분류 — 5단계 → 이지/보통/하드, 그리고 심박 우선

원래는 대회 페이스 기준으로 이지/마라톤/템포/인터벌/레페티션 5단계로 나눴는데, 존 경계가 좁아서(템포 구간이 14초/km 폭인 식) 페이스가 살짝만 벗어나도 점수가 0점으로 뚝 떨어지는 문제가 있었습니다. 두 가지로 고쳤습니다.

- **3단계로 단순화** — 이지/보통/하드. 롱런인지 마라톤 페이스인지 같은 훈련 유형 구분 자체를 없앴습니다.
- **판단 우선순위 변경** — 직접 태그 > **평균심박**(여유심박 %) > 페이스 자동분류. 트레드밀 보정까지 겹친 페이스 하나보다, 그날 실제 체감 강도를 심박이 더 직접적으로 반영한다고 봤습니다.

```ts
export function classifyIntensityFromHr(avgHr: number, maxHr: number, restHr?: number): IntensityZone {
  const pct = restHr ? (avgHr - restHr) / (maxHr - restHr) : avgHr / maxHr;
  if (pct < 0.72) return "이지";
  if (pct < 0.86) return "보통";
  return "하드";
}
```

그리고 점수 자체도 구간 경계를 살짝 벗어나면 바로 0점이던 걸, 반폭의 2.5배 거리까지는 완만하게 감쇠하도록 바꿔서 "절벽식 0점"을 없앴습니다.

## 3️⃣ 가민 Connect 자동 동기화 — 근데 2026년 3월에 API가 깨졌더라

수동으로 러닝 기록을 매번 입력하는 게 귀찮아서 가민 데이터를 자동으로 끌어오기로 했는데, 조사해보니 **2026년 3월 가민이 Cloudflare TLS 핑거프린팅을 도입**하면서 Node.js `fetch`, Python `requests`, `curl` 같은 비-브라우저 HTTP 클라이언트를 전부 차단해버린 상태였습니다. 가장 많이 쓰이던 비공식 라이브러리(`garth`, 구버전 `python-garminconnect`)가 그날로 다 죽었더라고요.

살아남은 방법은 `python-garminconnect`가 로그인을 `curl_cffi`(실제 브라우저의 TLS 핑거프린트를 흉내내는 라이브러리) 기반으로 다시 짠 버전이었습니다. JS 쪽은 대부분 헤드리스 Playwright 브라우저를 띄워서 우회하는 방식이라 Vercel 서버리스 함수엔 부담이 커서, 대신 **GitHub Actions에서 파이썬 스크립트를 6시간마다 돌려서 기존 관리자 API(`/api/data`)로 POST하는 구조**로 잡았습니다.

```yaml
on:
  schedule:
    - cron: "0 */6 * * *" # UTC 기준 6시간마다 = KST 03/09/15/21시
```

로그인 세션 토큰은 로컬에서 최초 1회만 로그인해서 만들고(비밀번호를 어디에도 저장하지 않기 위해), tar+base64로 인코딩해서 GitHub Actions 시크릿(`GARMIN_TOKENS_B64`)에 넣어뒀습니다. 이후로는 토큰만 복원해서 재로그인 없이 동작합니다.

## 4️⃣ 동기화하자마자 터진 중복 데이터

첫 동기화를 돌리자마자 두 가지 중복 문제가 바로 터졌습니다.

**① 이미 수동으로 입력해둔 기록과 중복** — 동기화 로직이 가민 `activityId`(garminId)로만 중복을 판단했는데, 기존 수동 입력분엔 당연히 그 값이 없어서 매번 새로 추가되고 있었습니다. 같은 날짜·비슷한 거리(±0.1km)·비슷한 시간(±60초)이면 같은 활동으로 보고 기존 기록에 garminId를 붙여 병합하도록 고쳤습니다.

**② 공식 대회 기록과 중복** — 과거 3년치를 백필했더니, 이미 공식 기록으로 등록해둔 대회일(하프·풀코스)이 "러닝 훈련"으로도 또 들어와서 그날 마일리지·훈련부하가 두 배로 잡혔습니다. 동기화 전에 기존 대회 날짜를 먼저 조회해서, 겹치는 날짜는 건너뛰도록 했습니다.

```python
race_dates = {r["date"] for r in existing.get("races", [])}
if date_str in race_dates:
    print(f"  {date_str} -> 건너뜀 (이미 공식 대회 기록으로 등록된 날짜)")
    continue
```

## 5️⃣ PB 판정 로직, 세 번 고쳐야 했던 이야기

예측 기록 카드 밑에 "내 PB"를 보여주는 기능을 추가했는데, 이게 세 번에 걸쳐 계속 틀렸습니다.

1. **1차**: 목표 거리 ±15%를 페이스로 비교 → 8.735km 뛴 걸 페이스로 늘려서 "10K PB"라고 보여줬습니다. 실제로 10K를 뛴 적 없는데 말이죠. → 목표 거리를 실제로 채운 기록만(최소 target×0.97) 인정하도록 변경.
2. **2차**: 여전히 이상했습니다. 알고 보니 순위를 **페이스**로 매기고 있어서, 10.005km/1:09:07보다 11.322km/1:16:07가 "페이스는" 근소하게 빨라 PB로 뽑히고 있었습니다. 실제로 더 짧은 시간에 완주한 건 전자인데 말이죠. → 페이스가 아니라 **완주 시간**으로 순위를 매기도록 변경.
3. **3차**: 심박 154bpm(여유심박 66%)인데 페이스는 거의 전력질주급인 트레드밀 기록이 PB로 잡히는 걸 발견했습니다. 트레드밀 거리 센서 오류로 거리가 잘못 찍혔을 가능성이 높다고 보고, 평균심박이 "이지" 강도로 분류되는 훈련 기록은 PB 후보에서 아예 제외했습니다.

세 문제 다 "그럴듯해 보이는 지표(페이스, 거리 근사치)를 실제 사실(완주 시간, 심박)보다 앞세운" 게 원인이었어서, 이번 참에 정직하게 실측값 위주로 다시 짰습니다.

## 6️⃣ 그 외 붙인 것들

- **훈련 로그 페이지네이션** — 백필로 8건 → 61건이 되면서 "최근 8개만" 보여주던 걸 4개씩 페이지 넘기는 방식으로
- **마일리지 캘린더 월 이동** — 이번 달 고정이던 걸 이전/다음 달로 넘길 수 있게
- **VO2max 추이 차트** — 동기화만 되고 화면엔 안 보이던 VO2max를 인바디 추이 옆에 막대그래프로
- **체중 변화 시뮬레이터** — "체지방·근육량을 얼마로 맞춰야 하는지" 같은 처방은 제가 함부로 할 수 있는 조언이 아니라서, 대신 이 앱이 이미 예측에 쓰는 체중 보정 공식(±5% 캡)을 그대로 가정법 계산기로 노출 — 지금 체중 대비 ±1~3kg이면 마라톤 기록이 얼마나 바뀌는지만 투명하게 보여줍니다

## 🛠️ 오늘의 삽질 — 사내망 SSL, 이번엔 파이썬 버전

지난 글에서 Node.js가 사내망 SSL 인터셉션(자체 서명 루트 인증서) 때문에 `NODE_EXTRA_CA_CERTS`를 걸어줘야 했다고 썼는데, 이번엔 가민 로그인 스크립트를 로컬에서 돌리다 `curl_cffi`가 같은 이유로 막혔습니다. `curl: (60) SSL certificate problem: self signed certificate in certificate chain`.

`curl_cffi`는 `REQUESTS_CA_BUNDLE`/`CURL_CA_BUNDLE` 환경변수를 읽는다는 걸 소스에서 확인하고, 기존 `corporate-ca.pem`을 `certifi` 기본 번들과 합쳐서 그 두 변수에 지정해주니 바로 해결됐습니다.

```python
combined = Path(tempfile.gettempdir()) / "pacelab_combined_ca.pem"
combined.write_bytes(Path(certifi.where()).read_bytes() + b"\n" + CORPORATE_CA.read_bytes())
for var in ("REQUESTS_CA_BUNDLE", "CURL_CA_BUNDLE", "SSL_CERT_FILE"):
    os.environ[var] = str(combined)
```

언어가 바뀌어도 "사내망은 모든 HTTPS를 가로챈다"는 원인은 똑같고, 매번 그 언어/라이브러리가 신뢰하는 CA 번들이 OS 기본값과 다르다는 것만 새로 알아내면 되는 문제였습니다.
