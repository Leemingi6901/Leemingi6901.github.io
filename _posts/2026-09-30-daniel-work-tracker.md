## 1️⃣ 스택 — DB 없이 시작해서, DB로 옮길 준비까지

- **Next.js 16** (App Router) + TypeScript + Tailwind CSS v4
- 저장소는 처음엔 **Vercel Blob** — 업무 하나당 JSON 파일 하나
- 비밀번호 게이트 로그인, Vercel Cron으로 매일 완료 업무 자동 보관
- 지금은 Postgres(Neon + Drizzle) 코드까지 들어가 있고, 스위치 하나로 전환 대기 중

혼자 쓰는 데이터라 "파일 하나 읽고 쓰기"로 충분할 줄 알았는데, 여기서 첫 번째 큰 삽질이 나왔습니다.

## 2️⃣ 삽질 1 — 상태를 바꿨는데 새로고침하면 되돌아간다

진행중으로 바꿔놓고 다른 탭에 갔다 오면 다시 이전 상태로 보이는 버그가 있었습니다. 처음엔 캐시를 의심해서 `no-store` 헤더에 캐시 MISS까지 확인했는데도 재현됐어요.

원인은 **Vercel Blob의 최종적 일관성(eventual consistency)** 이었습니다. `list()`가 돌려주는 메타데이터가 방금 한 덮어쓰기를 늦게 반영하는 경우가 있었던 거죠.

서버 쪽에서 100% 없앨 수 없어서, 결국 **"클라이언트가 더 최신 상태를 알고 있으면 오래된 응답은 무시한다"** 는 방어선을 뒀습니다.

```ts
function mergeFresh(server: Task[], known: Task[]): Task[] {
  const knownById = new Map(known.map((t) => [t.id, t]));
  return server.map((s) => {
    const k = knownById.get(s.id);
    return k && k.updatedAt > s.updatedAt ? k : s;
  });
}
```

이 경험 때문에 나중에 **저장소를 인터페이스 뒤로 숨기고 Postgres로 옮길 준비**를 하게 됐습니다. 전환 스위치를 `DATABASE_URL`이 아니라 `DATA_STORE=postgres`로 잡은 것도 같은 이유예요. DB를 연결하는 순간 변수가 생기는데, 데이터 이관 전에 배포되면 빈 DB를 보게 되거든요. Neon 없이도 테스트할 수 있게 인메모리 Postgres(PGlite)로 같은 마이그레이션을 돌려 검증하고 있습니다.

## 3️⃣ 쓰면서 붙인 기능들

한 번에 설계했다기보다, 쓰다가 불편한 걸 하나씩 없앤 순서입니다.

- **분류별 입력 양식** — 보안/인프라는 "장애·작업 + 장비명", IT 지원은 "요청자 + 요청 내용"처럼 분류마다 다른 양식
- **우선순위·체크리스트·드래그 정렬** (dnd-kit)
- **⌘K 명령 팔레트** — 업무·일정·메모 검색과 "새 업무" 같은 명령을 한 곳에
- **삭제는 확인창 대신 5초 되돌리기 토스트**
- **다크 모드** — 차트 색은 눈대중 대신 색각 이상까지 계산으로 검증
- **캘린더 구독(ICS)** — 휴대폰 캘린더에 마감일이 뜨게
- **텔레그램 아침 9시 알림** — 지난 마감 / 오늘 마감 / 오늘 반복 업무, 금요일엔 주간 보고까지
- **반복 업무 체크, 업무 템플릿, 메모 게시판(인수인계용), 기록 잔디**

그리고 로컬에만 있던 코드를 **비공개 GitHub 저장소로 옮기고 push = 자동 배포**가 되게 바꿨습니다. 이게 체감상 제일 컸어요. 예전엔 배포할 때마다 도메인 연결을 손으로 했는데, 알고 보니 도메인이 프로젝트가 아니라 특정 배포에 별칭으로만 붙어 있었더라고요.

## 4️⃣ 장비·솔루션 항목 — 보고서를 만들기 전에 데이터부터

사내 IT 담당자로서 보고서를 제대로 뽑고 싶어서 월간 보고서를 만들려고 보니 문제가 있었습니다. 장비명이 그냥 글자 칸이라, 같은 방화벽이 어떤 날은 `FW-01`, 어떤 날은 `fw 01`로 들어가 있었어요. 이대로 장비별 장애 건수를 세면 같은 장비가 두 줄로 갈라집니다.

그래서 환경설정에 **장비·솔루션 항목**을 등록하게 하고, 업무는 이름 대신 항목 id를 들고 있게 바꿨습니다. 기존 업무는 이름을 정규화해서(대소문자·공백·하이픈 무시) 자동으로 이어 붙였고요.

재밌었던 건 테스트하다 찾은 구멍입니다. `NAS-01`을 `NAS-01 본관`으로 이름을 바꿨더니 연결된 업무가 **2건 → 0건**이 됐어요. 기존 업무는 이름으로만 붙어 있었으니까요. 그래서 이름을 바꾸기 **직전에** 지금 연결된 업무들에 id를 먼저 박아두도록 고쳤습니다.

## 5️⃣ 월간 보고서 & 장애 보고서

항목이 생기니 월간 보고서는 **추가 입력 없이** 자동으로 나왔습니다.

- 완료 / 신규 접수 / 장애 대응 / 월말 진행 중 / 평균 처리 기간 / 당일 처리율
- 분류별 완료와 전월 대비 증감
- 장비·솔루션별 전체·장애·작업 건수
- 장애 내역, 주요 완료 업무, 다음 달 마감 예정

처리 기간을 타이머 없이 **접수일과 완료일의 날짜 차이**로 계산한 게 포인트예요. 헬프데스크 업무는 하다가 중간에 불려 가는 일이 많아서, 시간을 재는 방식은 애초에 맞지 않았거든요.

장애로 등록한 업무에는 **장애 보고서**가 붙습니다. 발생·복구 일시를 넣으면 장애 시간이 계산되고, 영향 범위 / 원인 / 조치 내용 / 재발 방지 대책을 적으면 `INC-202609-01` 같은 문서번호가 붙은 보고서가 됩니다. 두 보고서 모두 **PDF로 저장**(인쇄용 CSS로 메뉴는 빼고 A4로)하거나 마크다운으로 복사할 수 있어요.

## 6️⃣ 디자인 정리 — 그리고 하루씩 밀려 있던 마감 표시

기능을 빠르게 붙이다 보니 화면이 제각각이 돼서, 마지막으로 한 번에 정리했습니다.

- 10~11px 글씨를 전부 12px 이상으로, 흐린 글씨 명암비 **3.2:1 → 4.9:1**
- 버튼·카드·입력칸을 공통 부품으로 묶고, 초록은 "완료·선택됨" 상태에만 쓰기
- 대시보드 맨 위에 **"지금 처리할 것"** (마감 지남 → 오늘 → 우선순위 상)
- "불러오는 중…" 대신 회색 뼈대(skeleton), 빈 화면엔 다음 행동 버튼
- 휴대폰에선 창이 아래에서 올라오는 시트 + 오른쪽 아래 떠 있는 + 버튼

그리고 정리하다가 꽤 오래 숨어 있던 버그를 하나 찾았습니다. **오늘 마감인 업무가 "D-1"로 보이고 있었어요.**

```ts
// 마감일 23:59:59와 지금 시각의 차이를 "올림"
const days = Math.ceil((due.getTime() - now.getTime()) / 86400000);
// 오늘 마감 → 0.4일 → 올림 1 → "D-1"
// 어제 마감 → -0.6일 → 올림 0 → "오늘 마감"
```

오늘은 D-1, 어제 마감은 "오늘 마감", 이틀 지난 건 "1일 지남"… 전부 한 칸씩 밀려 있었습니다. 시각 대신 **로컬 날짜끼리의 차이**로 계산하게 바꾸고, 자정 직전·직후 경계까지 테스트에 넣었어요.

## 7️⃣ 마무리

이 프로젝트에서 반복해서 배운 건 두 가지입니다.

1. **데이터 모양 → 계산 → 화면** 순서로 가면 뒤가 쉬워진다. 장비 항목을 먼저 만들었더니 월간 보고서는 입력 없이 나왔어요.
2. **계산은 순수 함수로 빼서 테스트로 고정한다.** 보고서 집계, 잔디, 장비 연결, 알림 메시지까지 `npm test` 한 번에 6묶음이 돌아갑니다. 테스트를 쓰다가 제 기대값이 틀렸다는 걸 발견한 적도 있고요.

남은 큰 일은 Postgres(Neon) 전환입니다. 이관 스크립트와 스위치는 준비돼 있어서, 연결만 하면 끝나게 만들어 뒀습니다.
