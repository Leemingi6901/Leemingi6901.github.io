## 1️⃣ 목표와 원칙

목표는 두 가지입니다.

1. **업무 누락 방지:** 받은 요청이 기록되지 않거나 마감을 넘기는 일을 막습니다.
2. **고과 증적:** 반기·연간에 "무엇을 얼마나 했는지"를 숫자로 바로 꺼냅니다.

원칙도 정했습니다.

- **혼자 쓰는 앱:** 사용자 관리는 없고, "나만 쓸 수 있다"는 보장만 단단하게 합니다.
- **비용 0원:** 모든 서비스를 무료 한도 안에서 씁니다.
- **특정 업체에 갇히지 않기:** Vercel이 멈춰도 GitHub만으로 다시 띄웁니다.
- **판단은 순수 함수로:** 날짜, 알림, 집계 계산을 테스트로 고정합니다.

## 2️⃣ 전체 구성

```
 사용자: 웹/PWA · 슬랙 DM · 텔레그램
            │
            ▼
 cron-job.org(15분) ─▶ Vercel (Next.js 16) ◀─ GitHub Actions(백업)
 Vercel Cron(하루 1번) ─▶     │
                              ▼
                        Neon Postgres
 GitHub: main = 코드(푸시 = 배포) / backups = 데이터 스냅샷
```

| 구성 요소 | 역할 |
|---|---|
| Vercel | 앱, API, 하루 한 번 도는 크론 |
| Neon | Postgres. 운영 데이터 |
| GitHub | 코드, 백업 브랜치, 백업 자동화 |
| cron-job.org | 15분마다 알림 확인 호출 |
| Slack / Telegram | 알림 받기, 명령어로 업무 등록·완료 |

모두 무료 플랜입니다.

---

## 3️⃣ 저장소 — 인터페이스 하나, 백엔드 셋

모든 데이터는 `get / list / put / create / remove` 다섯 개짜리 인터페이스를 거칩니다. 환경 변수 하나(`DATA_STORE`)로 **Neon(운영) / Vercel Blob(예전) / 로컬 JSON 파일(복구용)**을 고릅니다.

`create()`는 "같은 id가 없을 때만 만들기"입니다. Postgres에서는 `ON CONFLICT DO NOTHING`으로 원자적으로 동작하고, 알림 중복이나 메신저 재전송을 막는 데 두루 쓰입니다. DB 표 변경은 배포 빌드가 자동으로 적용하고, 실패하면 배포가 멈춥니다.

---

## 4️⃣ 인증 — 들어오는 길마다 다른 열쇠

| 들어오는 곳 | 인증 |
|---|---|
| 웹 화면 | 비밀번호 로그인 → 세션 쿠키 |
| 백업 API | `CRON_SECRET` |
| 알림 tick | `TICK_SECRET` (이 키로는 알림 확인만 가능) |
| 텔레그램 | 봇 토큰에서 만든 비밀 헤더 + 내 채팅 ID |
| 슬랙 | 요청 서명(HMAC) + 5분 시간 제한 + 내 멤버 ID |

모든 비교는 상수 시간으로 합니다. 키를 붙여 넣다 섞인 공백이나 줄바꿈은 무시합니다. 인증에 실패하면 키 값 대신 **"받은 길이 / 기대 길이"만 기록**합니다. 실제로 이 기록 덕분에 "외부 스케줄러에서 키를 저장 안 했다"는 원인을 금방 찾았습니다.

## 5️⃣ 알림 엔진 — key 하나 = 기록 하나

알림은 4종류입니다.
- **평일 09시 업무 일보:** 어제 완료, 오늘 마감, 놓친 반복 업무 등
- **금요일 주간 요약**
- **17시 반복 업무 알림:** 완료 버튼 포함
- **회의 60분 전 알림**

15분마다 tick이 들어오면 이렇게 판단합니다.

1. 지금이 보낼 시간대인지 확인합니다. 밤이면 DB도 안 깨우고 끝냅니다.
2. 오늘 이미 보냈는지 기록 한 건만 확인합니다.
3. 필요한 데이터만 읽습니다.
4. 보낼 메시지를 계획합니다(순수 함수).
5. 메시지마다 `daily:2026-10-13` 같은 **key로 기록을 먼저 선점**합니다.
6. 보내고, 실패하면 선점을 풀어서 다음 tick에 다시 보냅니다.

동시에 두 번 호출돼도 선점은 한쪽만 성공하니 알림은 한 번만 갑니다. 회의 key에는 시각이 들어 있어서, 회의 시간을 바꾸면 다시 알려 줍니다.

**왜 GitHub Actions가 아니라 cron-job.org인가:** 처음엔 GitHub 예약 실행을 썼습니다. 그런데 백업 기록을 보니 00시 실행이 **4시간 44분 늦게** 돌았고, 12시 실행은 **아예 빠졌습니다.** 회의 알림에는 쓸 수 없는 정확도라 외부 스케줄러로 옮겼습니다.

## 6️⃣ 메신저 봇 — 슬랙·텔레그램에서 바로 등록

| 명령어 | 하는 일 |
|---|---|
| `/add 내용` | 업무 등록 |
| `/memo 내용` | 메모 저장 |
| `/today` | 오늘 볼 것 + 반복 업무 체크 버튼 |
| `/list` | 진행 중 업무 + 완료 버튼 |
| `/done 이름` | 반복 업무 체크·업무 완료 |
| `/help` | 안내 |

가장 재밌었던 건 **글 해석기**입니다. `/add MD팀 VPN 계정 요청 내일까지 #지원 !`를 보내면 다음처럼 나눠 저장합니다.
- 제목: "MD팀 VPN 계정 요청"
- 마감: 내일
- 분류: IT 지원
- 우선순위: 상

"금요일"은 처음 오는 금요일, "다음주 월요일"은 다음 주의 월요일로 계산합니다. "10/15"는 이미 지났으면 내년으로 봅니다. "오늘의 이슈"처럼 단어 일부인 경우는 마감으로 보지 않습니다.

명령어 로직은 한 벌만 있고, 슬랙과 텔레그램은 받는 방식만 다릅니다. 슬랙은 **3초 안에 응답**해야 해서 바로 "받았다"고 답하고 처리는 그 뒤에 합니다. 텔레그램은 느리면 같은 메시지를 다시 보내서, 메시지 번호로 한 번만 처리합니다.

## 7️⃣ 반복 업무와 성과 요약

반복 업무는 "규칙 + 완료한 날짜 목록"만 저장하고, 오늘 해야 하는지는 계산합니다. 규칙은 매일, N일마다, 요일, 매월 중에 고릅니다.

성과 요약은 고과용입니다.
- 완료 건수와 마감 준수율
- 평균 처리일과 당일 처리율
- 반복 업무 수행률(진행 중인 기간은 오늘까지만 셈)
- 장애 평균 복구 시간
- 부서별 IT 지원 건수
- 입퇴사 체크리스트 누락

이걸 숫자로 뽑아서 마크다운으로 바로 내보냅니다.

## 8️⃣ 백업과 복구

GitHub Actions가 하루 두 번 전체 데이터를 JSON 하나로 받아 `backups` 브랜치에 커밋합니다.

- 0건 백업은 서버가 거부합니다. 최신 백업을 빈 파일로 덮지 않기 위해서입니다.
- 전날보다 30% 넘게 줄면 경고를 남깁니다.
- 복구 스크립트는 0건짜리 백업을 건너뜁니다.

**새 PC 복구 시험도 실제로 해 봤습니다.** 빈 폴더에 GitHub에서 받고 `npm run restore` → `npm run dev:local`을 실행하니, 비밀값 파일 없이도 데이터가 그대로 떴습니다.

## 9️⃣ 마무리

정리해 보니 뼈대는 세 가지였습니다.

1. **저장소 인터페이스 하나:** 백엔드를 세 번 바꿔도 위쪽 코드는 그대로였습니다.
2. **key 하나 = 기록 하나:** 알림 중복, 재전송, 동시 호출을 같은 방법으로 막습니다.
3. **판단은 순수 함수:** 테스트 15묶음(2주치 알림 백테스트 포함)으로 고정해 두니, 슬랙을 붙일 때도 받는 부분만 새로 쓰면 됐습니다.
